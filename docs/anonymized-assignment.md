# Take-home programming assignment (v1.0)

The company has a positive problem. Requests for sales meetings and job interviews are increasing, while the team is still small and calendars are heavily booked.

Your task is to create a REST API to help find suitable times for a meeting. The API should take three arguments:

- type of the meeting;
- start of the meeting window;
- end of the meeting window.

The API should return a list of suitable times within the requested window together with a list of people.

Also create suitable documentation for the API.

You will be provided with two datasets:

- information about people and their skills;
- current calendar bookings for those people, represented as RFC5545 iCalendar published busy times.

You can and should define a suitable set of business rules for the booking logic. The following rules must be followed:

- For job interview bookings:
  - two people are required;
  - at least one person must have the skill `recruitment`.

- For sales meetings:
  - three people are required;
  - at least one person must have the skill `sales`;
  - at least one person must have the skill `software-architecture`.

The API should be deployed with Docker on localhost and exposed on port `8080`.

The repository should contain two Bash scripts:

- a script to create the deployable artifacts and deploy the solution;
- a script that calls the API using `curl` with parameters that return a non-empty result.

## Other considerations

- The solution should be testable on a standard Linux distribution with Docker, Bash, and curl.
- There is no need to save bookings; equivalent subsequent calls may return the same result.
- Use UTC times. There is no need to support timezone conversion.
- Use good REST conventions.
- Minimize the use of external dependencies.
- The primary design goal of the program is maintainability.
- Aim for a deployment containing only the minimum required components, with attention to image size and security practices.
- Avoid making the submission publicly available. A private repository may be used and shared with the relevant reviewers.
